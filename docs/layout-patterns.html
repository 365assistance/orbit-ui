ORBIT DESIGN SYSTEM

Page Layout Patterns

Reference for building Orbit app screens. These are the real, canonical page patterns the live Orbit app already uses. Start from the closest one, then remove the blocks you do not need. Do not invent a new page skeleton.

0The app shell

Every authenticated screen sits inside this fixed shell. A page template only controls what goes inside #main.
SIDEBAR

#main (page content, scrolls)
Sidebar is collapsible and becomes a mobile overlay under 768px. The skip-link is the first focusable element. Do not rebuild the shell per page.

6The non-negotiables

  • Page padding 32px on the PageContainer.
  • Section gaps 32px between header / metrics / data; 20px above the data panel.
  • Card gaps 20px in grids.
  • Radii panels use --orbit-radius-panel, controls --orbit-radius-control. Do not invent radii.
  • Elevation cards --orbit-elevation-card, hover --orbit-elevation-raised.
  • Color always tokens (--ink-primary, --border-default, --orbit-brand-primary, status tokens). Never a raw hex in a layout.
  • Type page title 28px bold, card title ~16px semibold, body 14px, metric value 26px bold.
  • Touch target controls respect --orbit-min-touch.
  • One h1 per page (the PageHeader title); headings descend in order.
  • Focus ring visible on every control (--orbit-focus-ring), never removed.

7Quick decision guide

You are designing...Use pattern
A list of records to manage1. Standard list page
A settings or create / edit screen2. Contained / form page
A single record's detail view3. Detail / entity page
A landing overview with numbers and charts4. Dashboard page
Any data surfaceadd 5. empty / loading / error states
If a screen genuinely does not fit any of these, flag it rather than inventing a one-off layout.
